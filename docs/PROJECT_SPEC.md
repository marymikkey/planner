# Планер — полное описание проекта (спецификация для воспроизведения)

Документ описывает текущее состояние проекта так, чтобы его можно было воссоздать с нуля. Код лежит в репозитории; здесь — что именно и почему.

## 1. Что это

Локальное (local-first) веб-приложение для личной продуктивности: планирование дня/недели, тайм-блокинг, задачи и рутины, работа / карьера и ML / учёба, здоровье, питание, финансы, аналитика. Без бэкенда, аккаунтов и трекинга. Данные — только в IndexedDB браузера. Работает офлайн, ставится как PWA. Интерфейс по умолчанию русский (переключатель на английский).

Цикл: Планируешь → Живёшь → Отмечаешь → Смотришь тренды → Корректируешь. Тон интерфейса — поддерживающий: никаких красных «провалов», серий и геймификации; прогресс показывается как «сделано X из Y».

## 2. Технологии и ограничения

- HTML + CSS + vanilla JavaScript (ES-модули). Без фреймворков, без сборки, без внешних шрифтов/CDN.
- Хранилище: IndexedDB (БД `planner-local`, версия 1). В `localStorage` дублируется только имя темы (чтобы не мигало при загрузке).
- Content-Security-Policy в `index.html`: `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; manifest-src 'self'; worker-src 'self'; base-uri 'none'; form-action 'none'` — страница физически не может отправлять данные на сторонние адреса.
- Нужен HTTP(S): модули и service worker не работают с `file://`. Любой статический сервер.
- Инструменты (не обязательны для работы приложения): Python 3 (`tools/serve.py`, `tools/make_icons.py`), Node (`tools/build-sw.mjs`).

## 4. Данные

Все записи: `id` (строка), `createdAt`, `updatedAt` (ISO). `updatedAt` ставит store при каждой записи — задел под будущую синхронизацию (Supabase). Даты — локальные строки `YYYY-MM-DD`; время суток — целые минуты от полуночи, значения ≥ 1440 означают «после полуночи того же планового дня» (при дне 05:00→01:00 событие в 00:30 хранится как 1470).

Хранилища IndexedDB (keyPath `id`): `tasks, events, routines, routineLogs, projects, roadmapGroups, roadmapTopics, subjects, healthEntries, meals, transactions, recurringTransactions, financeCategories, customMetrics, settings`.

- **task**: title, notes, area, projectId, subjectId, topicId, subcategory (Личное), priority P1|P2|P3, dueDate, dueTime "HH:MM", durationMin, actualMin, energy Low|Medium|High, status Inbox|Planned|In progress|Done|Skipped, tags[], scheduledDate, startMin, endMin, recurrence, createdDate, completedDate, nextGenerated.
- **event**: title, kind event|class|exam, area, projectId, subjectId, notes, date (якорь), startMin, endMin, recurrence, exceptions[] (даты-пропуски).
- **routine**: title, area, mode `fixed` (по recurrence) | `weekly` (target раз в неделю, без дней), recurrence, target, startMin, durationMin, startDate, exceptions[], archived.
- **routineLog**: id=`${routineId}_${date}`, routineId, date (одна отметка на рутину в день).
- **project**: name, area (Work|Career & ML), notes, deadline, archived. **subject**: name, notes, archived.
- **roadmapGroup**: name, order. **roadmapTopic**: groupId, name, status Not started|Learning|Practicing|Confident, progress 0–100, notes, resources[].
- **healthEntry**: id=date; опционально weight, bedtimeMin, wakeMin, sleepMin (считается), coffee, activity, activityMin, steps, mood, energy, stress, productivity, wellbeing (1–10), symptoms, notes, custom{metricId:value}. Сохраняются только заполненные поля.
- **customMetric**: name, type boolean|number|scale|category|text, unit, options[], archived.
- **meal**: date, time, type Breakfast|Lunch|Dinner|Snack|Other, description, tags[], calories, protein, fat, carbs (последние 4 — только если включено в настройках).
- **transaction**: date, type expense|income|savings, amount, categoryId (только для расходов), description, note, recurring, templateId. **recurringTransaction**: type, amount, categoryId, description, frequency monthly|weekly, startDate, lastGenerated, active — при запуске и смене суток из шаблона создаются реальные операции до сегодняшнего дня.
- **financeCategory**: name, limit, archived, order. По умолчанию 19 категорий (Rent … Other; без персональных, вроде лекарств конкретного человека).
- **settings** (одна запись id=`main`): language ru|en, theme light|dark|system, dayStartMin=300 (05:00), dayEndMin=1500 (01:00), weekStart=1, macros=false, currency=RUB, areaColors{}, personalCategories[Social, Appointments, Errands, Admin, Other], mealTags[coffee, sweet, fast food, home-cooked, restaurant, late meal], weeklyGoals{weekStartISO:text}, monthlyBudget, activityTarget=4, demo, onboarded, seeded, lastArea.

Первичное заполнение (`seeded`): категории финансов и 7 групп роадмапа (ML Core, Computer Vision, LLM, Agents, Interview Prep, Job Search, Pet Projects). Миграция: нетронутый день 06:00→01:00 превращается в 05:00→01:00.

Разделы (area): Work, Career & ML, Study, Health, Meals, Home, Personal, Finance. Цвета по умолчанию: #3a62b0, #1f9a73, #7a55cf, #d9587a, #e0662f, #cf9a2b, #a8449a, #b8860b.

## 5. Правила логики

- **Повторения** (`recurrence.js`): `{type: none|daily|weekdays|weekly(days[])|interval(every)|monthly, until?}`; `occursOn(rule, anchor, date)` вычисляется на лету, ничего не материализуется.
- **Задача «живёт» в** `scheduledDate || dueDate`. Просрочена, если активна и эта дата < сегодня.
- **Сортировка «Сегодня»**: просроченные → P1 → P2 → P3 → время (старт блока или dueTime) → дата создания. Отдельного «Топ-3» нет.
- **Сегодня** показывает активные задачи с датой ≤ сегодня; выполненные сегодня — в сворачиваемом списке.
- **Завершение повторяющейся задачи** создаёт следующую (ближайшая дата по правилу после max(якорь, сегодня)); флаг `nextGenerated` защищает от дублей.
- **Postpone** → завтра (или на день позже будущей даты); **moveTaskToDay** сдвигает scheduledDate и dueDate (если дедлайн не отличается от дня блока); **unschedule** убирает время, задачу оставляет.
- **Очистить день**: у задач дня снимается время, разовые события удаляются, у повторяющихся событий/рутин в `exceptions` добавляется дата (шаблоны целы).
- **Рутины**: недельный прогресс = отметки за неделю / ожидаемое (fixed: число вхождений в неделе; weekly: target). Пропуски не показываются как провал.
- **Сон**: wake > bed ? wake−bed : wake+1440−bed. Bedtime для аналитики: <12:00 → +1440.
- **Momentum** («Эта неделя»): время по Career & ML (actual иначе planned у выполненных), дни с активностью / цель, рутины Дома сделано/ожидалось, средний сон, число выполненных задач.
- **Финансы**: баланс месяца — доход, расходы, накопления, остаток бюджета = бюджет − расходы; превышение лимита категории подсвечивается нейтрально (янтарь, без красного).

## 6. Аналитика

`buildDaily(from,to)` отдаёт выровненные массивы по дням для метрик: weight, sleep(h), bedtime, coffee, activityMin, steps, mood, energy, stress, productivity, wellbeing, spend, tasksDone, focusHours + кастомные (number/scale/boolean). Скользящее среднее — трейлинг 7 дней по непустым значениям. Агрегация по неделям/месяцам (среднее или сумма по метрике). Планируемое vs выполненное — по неделям; время по разделам: плановая длительность vs введённое вручную `actualMin`. Корреляции: Spearman (средние ранги при совпадениях), лаг 0/+1/+2 дня, минимум 8 пар, подписи по |ρ|: <0.1 нет явной, <0.3 слабая, <0.5 умеренная, <0.7 сильная, иначе очень сильная; всегда пометка «Корреляция не означает причинно-следственную связь». Никакого ML.

## 7. Интерфейс

**Навигация (12 разделов):** Сегодня, Планер, Работа, Карьера и ML, Учёба, Здоровье, Питание, Дом, Личное, Финансы, Аналитика, Настройки. Хеш-роутер `#/<раздел>/<id?>`. Десктоп ≥900px — боковая панель + плавающая «+»; телефон — нижняя панель: Сегодня, Планер, [+], Аналитика, Ещё (шторка со всеми остальными разделами). Клавиша `n` — быстрое добавление.

**Быстрое добавление** (одна шторка, вкладки): Задача, Событие, Рутина, Расход, Приём пищи, Здоровье. Задача — название, раздел, проект/курс/категория, приоритет, срок, длительность; остальное под «Дополнительно».

**Сегодня:** дата и день недели, редактируемая цель недели; карточки: задачи (быстрый ввод по Enter), расписание (таймлайн), состояние (сон/вес/активность), рутины, «Эта неделя». На телефоне порядок: состояние → задачи → расписание → рутины → неделя.

**Таймлайн:** диапазон по умолчанию 05:00→01:00 следующего дня, автоматически расширяется вокруг любых элементов; пересекающиеся блоки рядом; линия «сейчас»; события — залитые блоки с цветной полосой, задачи — белые с пунктиром и чекбоксом, рутины — точечная рамка; нижняя «ручка» меняет длительность; шаг 15 минут; двойной клик по пустому месту создаёт событие.

**Drag-and-drop** (`dnd.js`): Pointer Events. Мышь — после 5px; касание — с ручки «⋮⋮» (touch-action:none) либо долгое нажатие 350мс на блоке; призрак за курсором, подсветка зоны, индикатор времени, автопрокрутка у краёв, подавление клика после броска. Зоны: таймлайн (запланировать/передвинуть), список задач и панель «Без времени» (снять время), колонки дня недели (перенести на день).

**Планер:** День (таймлайн + «Без времени» + «Входящие») и Неделя (7 колонок, на телефоне друг под другом, + недельные цели, + входящие), навигация ‹ Сегодня ›.

**Работа / Карьера:** карточки проектов (прогресс, дедлайн), страница проекта (задачи, прогресс, встречи, заметки с автосохранением); псевдопроект «Общее». Карьера: вкладки Роадмап / Задачи / Проекты; группы и темы редактируются целиком (статус, ползунок прогресса, заметки, ресурсы, связанные задачи).

**Учёба:** курсы, занятия (событие kind=class с повторением — автоматически в Сегодня/Планере), задания (обычные задачи с subjectId), экзамены (kind=exam), заметки курса.

**Здоровье:** чек-ин любой даты, все поля необязательны; рейтинги 1–10 кнопками (повторное нажатие сбрасывает); снимок дня, графики веса (точки + среднее 7д), сна, настроения/энергии; свои метрики.

**Питание, Дом, Личное, Финансы, Аналитика, Настройки** — как в README; в Настройках: язык, тема, диапазон дня и начало недели, макросы, валюта (RUB ₽ по умолчанию), цвета разделов, подкатегории Личного, теги питания, свои метрики, экспорт/импорт JSON, экспорт CSV по набору, демо-данные, сброс.

**Подтверждения** — только для удалений и замены данных; удаление задачи даёт тост «Отменить».

## 9. PWA и офлайн

`manifest.json` + `service-worker.js`: при установке кэшируется весь список файлов (генерируется `node tools/build-sw.mjs`, версия кэша — хеш содержимого); запросы того же origin — stale-while-revalidate; навигация офлайн отдаёт `index.html`. После изменения любого файла нужно запустить `build-sw.mjs`. На iPhone установка требует HTTPS-хостинга; данные привязаны к origin и устройству (перенос — экспорт/импорт JSON).

## 10. Локализация

Данные и логика используют английские идентификаторы (Work, Done, P1, названия категорий по умолчанию). `i18n.js` переводит текст при отображении: словарь точных строк + регулярные шаблоны для динамических фраз; `MutationObserver` переводит всё появляющееся в DOM (текст и атрибуты placeholder/aria-label/title/alt). «Свободные» шаблоны применяются только к атрибутам, чтобы не искажать пользовательский текст. Даты — `ru-RU`/`en-GB` по настройке, длительности — «1 ч 30 мин». Пользовательские данные не переводятся. Добавление языка = новый словарь + шаблоны.

## 11. Демо-данные

`core/demo.js`: детерминированный генератор (mulberry32, seed 42), всё вымышлено, даты относительно «сегодня»: 4 проекта, 2 курса, 13 тем роадмапа, события (в т.ч. повторяющиеся), ~19 открытых задач, ~45 дней выполненных, 6 рутин с отметками, 61 день чек-инов с лёгкими зависимостями (сон ↔ настроение), питание за 6 дней, финансы за 3 месяца, повторяющаяся подписка, лимиты категорий, две кастомные метрики.

## 12. Как воспроизвести

1. Создать структуру из §3. 2. Реализовать `core/` по §4–6 (db.js — тонкий IndexedDB-адаптер; store.js — Map-кэш + write-through + подписки; queries/actions — правила §5). 3. UI-кит `ui/` (функция `h`, контролы, шторки, dnd, таймлайн, SVG-графики, перестраиваемые по ширине контейнера через ResizeObserver). 4. Экраны `views/`. 5. Стили по §8. 6. PWA по §9, локализация по §10. 7. Запуск: `python3 tools/serve.py 8000`, открыть `http://localhost:8000`. 8. Проверка: прогнать все маршруты без ошибок в консоли; добавить сущности через «+»; перетащить задачу на таймлайн; экспорт → сброс → импорт и сверить количество записей; завершить повторяющуюся задачу и убедиться, что создалась следующая; корреляция на демо-данных (сон ↔ настроение) должна быть положительной.

## 13. Отложено

Перестановка групп/тем роадмапа перетаскиванием; исключения отдельных вхождений повторяющихся событий (сейчас перенос меняет все); напоминания; синхронизация (Supabase); автотесты; ML-модели поверх `buildDaily()`.
